## B01：重复稀疏坐标在原始数值类型中合并，可使正表达变零

**优先级 P1；特殊存储条件下会改变统计结果。**

位置：[preprocess.py](../cellmesh/preprocess.py) `_compute_celltype_expr_frac()` 第 312 行；[permutation.py](../cellmesh/permutation.py) `_pseudobulk()` 的 `local_x > 0.0`；[plotting.py](../cellmesh/plotting.py) `_expression_columns()` 第 1996–1997 行。

触发条件：CSR/CSC 同一 `(cell, gene)` 坐标有多个存储条目，尚未合并，并且合并值超出其原始类型范围。这与重复基因列名、显式存储零不同。数值大于零的计数规则本身正确，缺口在于比较/转为稠密前没有安全处理重复坐标。

最小复现矩阵：

```python
X = scipy.sparse.csr_matrix(
    (numpy.array([2, 80, 80, 2, 1], dtype=numpy.int8),
     numpy.array([0, 1, 1, 0, 1]), numpy.array([0, 3, 5])),
    shape=(2, 2),
)
# 列为 G、R；行分别为细胞类型 A、B。
# 原始存储包含两个 (A, R)=80；其合计应为 160。
```

用 G 作为 HMDB1 的生成基因，R 作为受体，设置 `min_cells=1`、`min_expr_frac=0.1`、`n_perms=9`：

| 指标 | 当前 int8 重复坐标输入 | 先升 float64 再合并的对照 |
|---|---:|---:|
| A 的 R pseudobulk | 160 | 160 |
| A 的 R 表达比例 | 0 | 1 |
| A→A 事件分数 | 0 | 0.5471529031 |
| A→A p 值 | 1 | 0.7 |

原因是 pseudobulk 使用 float64 累加；而稀疏 `>0` 比较会在原始 int8 中合并重复值，`80+80` 溢出为 `-96`，产生自相矛盾的均值和表达比例。小提琴取值先 `toarray()`、再转 float，也会先得到 `-96` 并报错。uint8 的重复值可回绕成 0；int16 也复现评分和 p 值变化。

**影响范围。** 已在 CSR/CSC、pooled/sample-aware 均复现。启用 `min_expr_frac` 时影响 receiver gate、事件分数及 p 值，继而可能影响 FDR；不启用 gate 时至少表达比例元数据仍错。普通非重复坐标矩阵不触发此问题。当前 `demo_HNSC_200cell.h5ad` 为 dense float32，`test_single_cell.h5ad` 为已规范化的 CSR float32，均不满足触发条件。float32 的本次评分对照未出现分数或 p 值差异，不能将整数复现结论泛化为所有 dtype。

**建议方案。** 保留现有原始相关表达值校验，在计算使用的稀疏副本中先提升数值类型，再安全合并重复坐标；观测表达比例、置换和小提琴共用该处理。保持稀疏存储并不修改调用者矩阵，合并后继续检查非有限值。不能只补一条绘图路径，也不能等发生溢出后才转换类型。

**验收。** 重复/非重复 CSR、CSC、支持的 sparse array、不同整数/浮点类型、指定 layer、普通/backed 以及两种推断模式，与安全合并后的对照比较表达比例、分数、p/FDR 和图形输入；显式零和原对象不变继续验证。

## B02：事件图的 QC 列未校验类型，文本 True 被当成不通过

**优先级 P2；外部结果表的显示/防错问题。**

位置：[plotting.py](../cellmesh/plotting.py) `_apply_min_cells_event_qc()` 第 239 行。

该函数直接 `passes_min_cells.eq(True)`。布尔 `True` 正常；字符串 `"True"` 和非法字符串 `"bad"` 都被计为 QC 失败，没有格式错误提示。相同 4 个事件仅将 QC 列改为字符串，计数图由 4 变成 0。在独立单事件复现中，network、dotplot、sample-event 图也都因 QC 后为空而报错。

**影响范围。** 事件计数、网络、dotplot、样本事件分数四种图共用此函数。常见触发入口是外部 DataFrame，或使用 `pd.read_csv(..., dtype=str)` 保留标识后绘图。程序直接生成的 bool/nullable boolean 结果不受影响；这不是普通 CSV 默认读取必然出现的问题。计算结果本身不被修改。

**建议方案。** 在共用入口明确 QC 列契约并转换：支持布尔值和可识别的 True/False 文本；保留真正 NA，其他非法值显式报错。现有 0/1 是否保留兼容应统一规定，不能将任意数值或文字当作失败。`qc_only=False` 时也校验用于报告的 QC 元数据。

**验收。** 四个接口覆盖布尔、nullable boolean、文本往返、NA、非法文本和混合类型；正确转换不改变筛选结果，NA 不被伪造为通过，错误输入不再表现为“无事件”。

## B03：外部 cell_fractions 在类型检查前强制转换，复数虚部被丢弃

**优先级 P2；独立评分接口的异常输入防错问题。**

位置：[score.py](../cellmesh/score.py) `_resolve_cell_fractions()` 第 51 行。

`pd.Series(cell_fractions, dtype=float)` 在检查之前执行。`[0.5+20j, 0.5+30j]` 会在发出 `ComplexWarning` 后变成 `[0.5, 0.5]` 并继续评分；dtype=object 中的复数也复现。单个细胞类型传 `[True]` 会被解释为 `[1.0]`。

**影响范围。** 显式传入 `cell_fractions` 的 `compute_metabolite_availability()` 和 `cellmesh.score.compute_sensor_scores()`。前者的比例参与 sender 丰度权重及评分；后者只将比例存为描述性元数据。`run_cell_mesh()` 自行计算正常比例，没有该异常输入入口。自定义合法比例是否与实测比例不同不列为本项缺陷。

**建议方案。** 先检查原始标量类型，拒绝复数、布尔和日期等不应作为比例的值；再转换合法实数或明确支持的数值文本，并执行现有有限、严格正值、索引及总和检查。可复用受体摘要已有的严格数值校验规则。

**验收。** 两个独立接口覆盖 native/object 复数、布尔、非法文本、有效实数、数值文本、NA/Inf；非法输入在类型转换前报出明确错误，默认及合法自定义比例保持原结果。
