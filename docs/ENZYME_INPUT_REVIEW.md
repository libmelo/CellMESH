# Enzyme 输入处理复核

已修复多基因字段在标准 `role` 表中未拆分、被表达基因匹配误删的问题，
以及复核发现的反应去重顺序和重复别名列校验问题。
复核范围包括数据库读取、运行时校验、直接 availability 计算、反应分组和编译置换评分。

## 已修订并验证

- `role`、`direction`、两者同时存在且含义一致的表，以及旧字段名，统一拆分 `gene`。
- 支持分号、逗号、竖线及混合分隔符；`[证据]` 内的分隔符保留为注释内容。
- 拆分发生在表达基因匹配之前；直接调用 `validate_priors()` 也使用共同标准化函数。
- 拆分保留反应编号、HMDB ID、既有证据、来源和自定义元数据类型。已有证据列优先，
  没有该列时保留行内证据。空基因条目被忽略，同一反应重复基因不会重复增加活性。
- 评分层只接收标准化后的单基因记录，删除了独立的分隔符和注释解析代码。
- 回归测试覆盖 CSV/DataFrame、两种样本模式、P/C/E、反应数量、发送端评分、
  置换 p 值、FDR、完整 null scores，以及编译评分与重新运行公共接口的比较。
- 当前默认库标准化后的 enzyme 11,687 行、interaction 6,478 行与多基因修订前逐项一致；
  enzyme 再次标准化后也保持一致。数据库文件未修改。

测试见 `tests/test_enzyme_multigene.py`、`tests/test_enzyme_reaction_consistency.py`、
`tests/test_enzyme_aliases.py`，另保留既有输入兼容性、availability 和置换测试。
两项遗留修订新增 77 项测试；该阶段完整测试为 **463 通过、1 跳过**。

## 两项遗留问题的修订结果

以下两类问题均已修订，并用原来的复现条件验证。

### 1. 统一按完整先验去重，再用可测得基因评分

同一代谢物、同一角色有两个反应：

| 反应 | 完整基因集合 |
|---|---|
| r1 | G1、MISSING |
| r2 | G1、G2 |

表达矩阵包含 G1、G2，不包含 MISSING。两个细胞类型 A、B 各占一半，
G1 的均值分别为 4、1，G2 的均值分别为 9、4。

- 修订前，`run_cell_mesh()` 先在 `validate_priors()` 中删除 MISSING，再按基因集合去重。
  r1 此时为 `{G1}`，成为 r2 的严格子集，被省略，P 为 `[3.035534, 1.081139]`。
- `compute_metabolite_availability()` 按完整集合去重。两个集合互不包含，均被保留；
  每个反应再使用其中可测得的基因计算，P 为 `[5.035534, 1.581139]`。

修订后两入口均保留 r1 和 r2，P 均为 `[5.035534, 1.581139]`。
主流程通过 `filter_enzyme_genes=False` 获取完整的有效 enzyme 先验，用于观测、
置换和证据状态报告。反应去重后才选可测得的基因；完全不可测得的反应容量为 0，
其反应定义和先验状态仍保留。整个 enzyme 先验都无法匹配表达基因时，主入口仍明确报错。

测试同时检查 P/C/E、反应数量、显示名称、未测得/零表达/无先验状态，以及两种样本模式的
编译评分与完整重算、串行与并行置换结果。本修订可能改变此前受缺失基因去重影响的评分。

### 2. 重复别名列统一比较、补齐和冲突报错

修订前部分重复别名列会静默择一，修订后的规则为：

| 输入 | 修订后结果 |
|---|---|
| 没有 role，Direction=substrate，direction=product | 冲突报错，指出列和行 |
| 没有 role，Direction 为空，direction=product | 补齐为 production |
| export、exporter、transporter 方向别名同时存在 | 含义一致，合并为 export |
| gene=G1，Gene_name=G2 | 冲突报错 |
| hmdb_id 与 HMDB_ID 内容不同 | 冲突报错 |
| reaction 与 Reactions 内容不同 | 冲突报错 |
| metabolite 与 standard_metName 内容不同 | 冲突报错 |
| DataFrame 或 CSV 存在完全同名的重复列 | 明确报错，避免 CSV 自动改名掩盖歧义 |

所有别名在丢行前校验。标准化后相同则合并，空值由非空列补充。基因列表按共同解析规则
比较集合，合并保留行内证据；同一个基因的不同注释保留为证据记录，不重复增加反应活性。
既有 evidence_level 列仍优先。合并后只保留标准列，重复标准化和 CSV 往返保持一致。
当前默认 enzyme 文件没有这些重复别名列，数据库文件和 interaction 处理逻辑未修改。

## 后续关联绘图复查

统一 AnnData 标识时，复查了表达分布绘图：完整反应定义中包含未测得基因时，
旧的表达取列函数会直接报错。现已按评分规则保留反应定义，仅使用测得的基因；
某条反应没有测得基因时，其贡献为 0。所有生产基因都不可测得的代谢物，
仍按既有评分规则不生成正式发送端结果。

回归测试同时覆盖部分基因缺失，以及可计算反应与完全不可测得反应并存的情况，
检查生产活性、完整反应定义和实际使用的基因。测试见
`tests/test_identifier_normalization.py`；本轮完整测试为 **507 通过、1 跳过**。

## 复核结论

两个已确认的遗留问题均已关闭。本次还检查了 6 组随机生成的完整反应先验与重复别名输入：
在 pooled 和 sample-aware 模式下共 18 个计算单元，两入口的 P/C/E、发送端评分、
反应集合和元数据均逐项一致。默认数据库标准化后的内容、数据类型和列顺序保持一致。
在本次覆盖的输入、缺失基因和评分路径中，未发现新的同类遗留问题。

此前受缺失基因改变反应包含关系影响的分析，应重新运行以获得修订后的结果。
