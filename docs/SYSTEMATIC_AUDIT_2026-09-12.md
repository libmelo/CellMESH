### A01：名称仍能影响样本汇总结果

审查时位置：`core.py:67、620、630、662、796`；`docs/METHODS.md:4、40`。

**问题及原因。** 主流程连接 sender/receiver 时已按 HMDB 匹配，但 sample-aware 的 sender 中位数、receiver 汇总和事件汇总仍包含 `metabolite` 分组键。pandas 的默认 `groupby(dropna=True)` 会删除键中带 NA 的组。只修绘图标识，没有覆盖这些上游分组。

**复现。** 8 个细胞、2 个样本、2 个细胞类型、1 个 HMDB 和 1 个受体，表达及 ID 完全相同，仅改变名称：

| 名称条件 | pooled 事件数 | sample-aware 事件数 | sample-aware sender 行数 | sample-aware receiver 行数 |
|---|---:|---:|---:|---:|
| 两侧名称正常 | 4 | 4 | 1 | 2 |
| Enzyme 名称缺失 | 4 | 0 | 0 | 2 |
| Interaction 名称缺失 | 4 | 4 | 1 | 0 |
| 两侧名称缺失 | 4 | 0 | 0 | 0 |

样本级原始事件仍有 8 行，消失发生在汇总阶段。CSV 空单元格也能触发。当前默认数据库名称非空，未在该库上复现这一缺失。

此外，`_make_cell_mesh_events()` 对非 MultiIndex sender 表仍按名称查找；相同名称可以在未证明 HMDB 相同的情况下构造事件。正常主入口生成的表不走此后备分支，但它与当前身份规则冲突。

**方案。** 关系身份为 `hmdb_id + sensor_gene`，事件上下文为 `sender + receiver`，样本记录再加 `sample`；sender 矩阵汇总只以 HMDB 为身份。名称及 sensor_type 作为注释携带，类型一致性沿用先验检查。删除名称后备匹配，对无法提供 ID 的输入明确报错。展示名称允许缺失，优先使用可用名称，否则显示 ID；同步纠正方法文档对“名称必需非空”和事件定义的表述。

**验收。** 名称缺失、别名、同名不同 ID、同 ID 不同基因、CSV/DataFrame、两种模式均不改变事件身份、评分及 p/FDR；样本汇总、null 索引、导出和 6 种图同步验证。

**修订记录（2026-09-13）。** 已统一发送方 HMDB 汇总、接收方 HMDB/基因/receiver 汇总和四字段事件键；名称及类型从身份键中移除，结构性 NA 样本行按事件 ID 重新附加注释。sender 展示索引和 CSV 标识列继续保留，null 索引改为 `sender、receiver、hmdb_id、sensor_gene`。旧名称匹配后备分支已删除；无有效 Enzyme 名称时使用 Interaction 名称，仍缺失时使用 ID。直接评分使用相同的有效名称/ID 回退规则，图中 ID 回退不重复写成 `ID (ID)`。项目和数据库目录说明已同步。

### A02：解析器隐式修正绕过原始输入检查

位置：`database.py:80–102`、`io.py:183–189`。

**先验 CSV。** 表头检查了重复，但正文没有检查隐式索引。表头 4 列、数据 5 项时，pandas 可把第一项自动用作索引，剩余数据整体错位。例如：

```csv
metabolite,hmdb_id,sensor_gene,sensor_type
M,HMDB1,S,Transporter,EXTRA
```

加载后得到 `metabolite=HMDB1、hmdb_id=S、sensor_gene=Transporter、sensor_type=Other receptor`。对应 Enzyme 超宽行则可能被当作无效角色过滤成空表。问题发生在别名和值校验之前，后续错误可能只表现为“找不到基因”。

**10X。** `scanpy.read_10x_mtx()` 默认将重复符号改为唯一名称。原始 features 中两个 `G` 被读成 `G、G-1`，后续唯一性检查通过，而 Enzyme/Interaction 中的 `G` 仅匹配第一列。legacy 与 modern gzip 10X 均已复现；与 CSV、MTX 当前的重复标识规则不一致。

**方案。** 先验读取检查正文列宽和隐式索引，给出原始记录位置，保留合法引号、逗号及多行字段。10X 禁止默认自动编号掩盖重复，在原始名称保留下来后执行统一标识检查；调用者需要明确选择符号或基因 ID 的匹配方案。

**验收。** 两类先验、混合正常/超宽行、合法引用字段、10X legacy/modern、压缩/未压缩、重复/去空白后重复/合法带后缀名称均覆盖。

**修订记录（2026-09-13）。** 两类先验 CSV 现在逐条检查逻辑记录，正文项数必须与表头一致；缺字段、超宽、引号不闭合或 NUL 文本均报告文件及原始物理行位置。继续拒绝重复表头，并检查 pandas 解析后未生成隐式索引。合法引号、逗号、多行字段、显式空字段和压缩文件正常读取；跳过记录外的空白行，但不把引号包裹的空字段当作空白行。DataFrame 自定义索引继续有效。代码注释明确禁止以仅检查表头、截断或跳过坏行为优化替代。

10X 现在先读取原始注释文本，再检查所选基因轴和细胞条码；去除首尾空白后重复、空标识或记录宽度/矩阵维度不符时明确报错，重复基因诊断包含原始 ID、符号和记录位置。默认使用 `gene_symbols`，不再自动添加后缀；显式 `make_unique=True` 也会报错。需要使用唯一基因 ID 时可选择 `var_names="gene_ids"`，同时必须让两类先验使用相同标识体系。合法原名 `G-1`、前导零和字面量 `NA` 保留。现代格式先按 `gex_only` 选择特征，再检查所选轴的唯一性。

legacy/modern 的压缩和未压缩布局、逐文件混合 gzip 及文件名前缀均已支持，冲突文件不会被静默择一。数值矩阵继续由 Scanpy 读取并支持缓存；每次调用仍检查当前原始注释。缓存矩阵更新规则沿用 Scanpy，替换源矩阵后应关闭或清理旧缓存，详见[读取规范](ANNDATA_README.md)。项目、方法及数据库目录规范已同步。

新增 [先验 CSV 结构测试](../tests/test_prior_csv_structure.py) 和 [10X 读取测试](../tests/test_io_10x.py)，合计 **92 项回归用例**；除上述格式和错误输入，还比较四种 10X 布局与原生 AnnData 在两种推断模式、`n_perms=0/5` 下的分数、p/FDR 和 null 结果。最终全量验收为 **1147 passed、1 skipped、213 warnings，138.50 秒**；跳过项及 AnnData 警告与 A01 验收相同。A02 已关闭，同时关闭 A10 的 10X 读取子项。

### A04：有限且非负仍不足以保护极小正数

位置：`_numerics.py:13`、`score.py:591、693`、`permutation.py:177、284、360`、`core.py:808`、`plotting.py:1708、1817`。

以下均已复现，属于同一组数值稳定性问题：

| 条件 | 当前结果 | 影响 |
|---|---|---|
| 单基因反应表达为 `1e-20` | `gmean(x+1)-1 = 0` | 真实正表达被记为 `prior_no_expression`，事件变零；小提琴的 `log1p/expm1` 路径仍为正 |
| `P_score≈2e-200、C_score=0` | 先平方下溢，base=0 | 按公式应约等于 `2e-200` |
| sender≈`2e-160`，receiver=`2e-200` | 先相乘下溢，event=0 | 稳定计算可得到约 `2e-180` |
| 两组细胞比例均为 0.5，指数为 2000 | 权重均为 0，所有事件变零 | 相同丰度因子本应在归一化中抵消，不能解释成没有表达 |
| 小提琴值 `[0,1e-9,2e-9]` | `np.allclose` 判为常量，画在第一个值 0 处 | 有变化的数据被显示成全零常量 |

这些 0 都能通过“有限且非负”检查。前两类涉及加减抵消、乘方下溢；丰度例子涉及中间量超出 float64 可表示范围；小提琴则用了有绝对容差的“近似相等”判断。

**方案。** 共享稳定的等价公式：反应使用 `expm1(mean(log1p(x)))`；base 使用 `P_score * (P_score / denominator)` 并保留零分母规则；事件使用 `sqrt(sender) * sqrt(receiver)`。对仍无法表示的正权重/容量下溢明确报错，不能继续标成“无表达”。单细胞图仅对真正恒定值退化为横线，KDE 数值退化另作处理。观测、置换和单细胞展示同时修订，共用关键数值函数。

**验收。** 普通量级结果符合原公式；极小正数在可表示时保持为正；真正的零仍为零；不可表示的中间量报错；常量输入 p=1、正值与结构性 NA 的区别，以及串/并行一致性都继续成立。

### A05：计算入口的可选参数与缓存校验不完整

位置：`score.py:143–240`、`core.py:997、1120`。

**受体缓存。** 直接调用 `cellmesh.score.compute_sensor_scores()` 并传入摘要时，原始 X 被检查，但 `expr_frac`、`cell_counts` 和缓存的完整观测覆盖没有同等校验。

- `expr_frac=-1` 被接受并把 receiver gate 关闭；
- `expr_frac=NaN、Inf、2` 仍可返回正分数，NaN 与 gate 比较为 False；
- AnnData 有 A、B 两组，提供仅有 A 的 pseudobulk，会只对 A 求参考并返回 `0.5`；完整两组表达为 2、8 时 A 应为 `2/(2+5)=0.285714`；
- `cell_counts={"A": -1.5, "B": 1.9}` 被接受并截断为 `receiver_n_cells=-1、1`，错误计数还进入 QC 标记。

正常 `run_cell_mesh()` 内部生成的缓存没有在本次测试中出现这些异常；风险在允许传入外部摘要的入口。

**布尔开关。** `allow_self="False"` 被当作真值，仍产生自分泌事件；`False` 才会排除。它影响事件集合和 FDR 范围。

**随机种子。** `n_perms=0` 时，`random_state=float("nan")` 未经验证直接进入结果参数；后续还可导致 A09 的非法 JSON 输出。虽然本次未运行置换，但参数合法性不应随置换次数改变。

**方案。** 校验缓存索引/列的规范化与唯一性、全部观测细胞类型及所需基因的覆盖、表达比例范围和细胞计数；计数须为合法整数并与实际观测一致，不得靠强制转换截断。不以重新计算全部表达矩阵替代必要的廉价一致性检查。布尔计算开关统一接受明确的布尔值，字符串及其他含混类型给出清晰错误；即使 `n_perms=0`，也按接口约定检查 `random_state` 的类型和取值。

**验收。** 合法缓存与无缓存结果相同；部分、重复、负值、非有限、越界缓存提前报错；参数不能通过 Python 真值规则静默扩大事件集合；非法种子在零次和正数次置换入口均被拒绝。

**修订记录（2026-09-13）。** `compute_sensor_scores()` 现在以当前 AnnData 的实际观测标签和已测先验受体基因为依据，检查 `pseudobulk`、`expr_frac` 及 `cell_counts`。两类摘要矩阵必须覆盖全部实际观测类型和所需基因；多余细胞类型、表达矩阵之外的基因、空标识及规范化后的重复标识均报错。允许列中保留同一表达矩阵的其他基因；只对参与受体评分的数值进行检查。合法摘要按标识对齐，调用者对象保持不变，已提供的表达摘要不重复计算。

相关平均表达必须有限且非负，表达比例必须有限且位于 `[0,1]`，即使未启用 gate 也检查。数值文本可显式转换；非法字符串、布尔值、复数、日期及数值缺失不能被静默编码或填零。细胞计数先检查正整数值及与实际 obs 计数的一致性，再返回整数；`2.0` 等整数值可用，`-1.5、1.9` 不再被截断。原始表达检查继续执行。摘要校验保证结构、覆盖及数值范围，无法仅凭这些信息证明摘要来自当前 X/layer，调用者仍负责缓存来源一致性。

未使用的分类水平不视为观测类型；低细胞数和实测全零类型继续保留。sample-aware 按当前样本的实际类型检查，不要求每个样本覆盖全局所有类型；缺失端点形成的结构性 NA 继续保留。`allow_self`、`store_null_scores`、`return_intermediates` 统一只接受 Python/NumPy 布尔值。`random_state` 按现有整数接口只接受非负 Python/NumPy 整数，主入口在零次置换和空事件提前返回之前校验，并规范化为 Python 整数。

新增 [216 项回归用例](../tests/test_scoring_input_contracts.py)，覆盖独立/组合摘要、mean/median、gate 开关、缺项/多项/重复/空标识、非法数值与计数、零表达及 QC、样本内覆盖和指定 layer、合法摘要不变及不重算、两种模式和零次/正数次置换的参数检查，以及合法种子的串并行分数、p/FDR 和完整样本 null 一致性。最终全量验收为 **1363 passed、1 skipped、213 warnings，147.98 秒**；跳过项及 AnnData 警告与 A02 验收相同。README 接口规范、方法说明和实现说明已同步，A05 已关闭。A09 的导出器严格 JSON 预检仍待单独修订。

### A06：绘图入口校验与规范化仍有多处分支差异

位置：`plotting.py:238、444–457、931–1016、1060、1126、1329、1361、1559–1584、1652、1699`。

本组覆盖所有相关绘图入口，不能只修 dotplot 的一个统计列：

| 已复现的输入 | 当前行为 |
|---|---|
| 计数图/网络图的 FDR 为 `-0.1` 或 `-Inf` | 仍计为满足显著性阈值 |
| dotplot FDR 字符串 `["1e-2","0.5","0.9"]`，top_n=1 | 先按字符串排序，选中 0.5 而非 0.01 |
| dotplot 分数为 NA/Inf | 返回表仍说该行已绘制，Matplotlib 实际把该点屏蔽 |
| 样本分数为 `"bad"` | 被 `errors="coerce"` 变为 NA，图上解释为“事件不可计算” |
| 样本分数为 Inf 或负数 | 未拒绝；负柱被从 0 开始的坐标轴裁掉，汇总中位数仍受影响 |
| dotplot 大小范围反向、负数、NaN 或 Inf | 显著性与大小关系可反转，或产生不可见点/警告 |
| 来源分组标签被规范为 A，选择参数仍传 `" A "` | dotplot、network、sample plot 找不到本应匹配的记录 |
| 外部 reaction_genes 中 `["G1","G2"]` 改为含空白或重复符号的等价列表 | 比较键去重了基因，但实际表达计算仍用原列表，结果随表示方式改变 |

最后一项限于自行构建/改写的结果对象；正常主算法已提供规范化反应定义。实测两基因表达 4、9 时，正常反应小提琴值为 6.071068，`[" G1 ","G2"]` 变为 9，`["G1","G1","G2"]` 变为 5.299605。

**方案。** 选择相关上下文后，先生成统一的数值视图和合法性检查，再阈值筛选、排序、去重与绘制。p/FDR 和表达比例按 [0,1] 检查，原生 CELL MESH 得分按其范围检查；自定义 score 列按明确契约处理。真实 NA 保留其含义，非法字符串/Inf 不得冒充 NA。绘图数据和选择参数使用同一标识规范；反应列表的规范化结果必须实际用于取基因和计算。大小与颜色范围须有限且有序。

**验收。** 非法值在各图及各统计分支行为一致；科学计数法字符串按数值排序；返回的绘制行数与可见点一致；NA 样本与数值失败明确区分；选择器和等价反应表示不改变匹配/计算。

### A07：p/FDR=0 的大小和图例含义错误

位置：`plotting.py:1078–1081、1205–1222`。这是此前已确认的待修订项之一。

当前用最小正概率作为所有 0 的下限：

- FDR `[0,0.01,0.1]` → 大小 `[260,260,20]`，图例把 0 与 0.01 表示成同一个值；
- FDR `[0,1,1]` → 全部大小 140，图例只有 1；
- FDR 全为 0 → 图例出现输入中不存在的 `1e-12`。

p-value fallback 同样受影响。当前核心的加一置换 p 值不会产生 0；本项主要影响外部结果或经舍入的统计表，不表示核心重新出现了 p 值计算错误。

**方案。** 正概率维持其真实数值顺序，0 使用独立且明确标注的显示上限；图例必须能识别 0。覆盖全零、零与 1 混合、极小正数及 NA 混合，不改写输入概率。

**验收。** 正值间的大小排序正确；0 不被标成任何正概率；FDR 和 p 两个分支、自动和外部 axes 均通过。

### A08：完整显著性分支的图例仍重叠或越界

位置：`plotting.py:1099–1109、1199、1234`。这是此前另一项已确认的待修订项。

预留图例空间的修订依赖 `has_missing`。全部统计值可用时，外部 `ax` 的图例仍覆盖全高色条，FDR/p 两个分支都复现。默认分面中，p-value 图例标题也可越过画布：两个 sender、长度 10 的名称时，图例右边界 **930.60 px**，画布仅 **900 px**。短名称、单 sender 并非必然越界。

**方案。** 以实际图例和色条空间统一布局，不把修正仅限定在缺失分支。为外部 axes 明确预留空间或采用可控的附属图例区域。长标签在调用者提供的紧凑画布上的限制，也应明确记录。

**验收。** 使用 renderer 边界检查及目视核对，覆盖 FDR/p、全有/部分 NA/全 NA、单/多 sender、短/长名称、自动/外部 axes；检查相互遮挡和画布越界。

### A09：结果结构与重复导出的文件集合不稳定

位置：`core.py:128–173、933–937、1202`。

**残留文件。** 先用某前缀导出 sample-aware，再用相同前缀导出 pooled，parameters 已写为 `pooled_stratified`，但旧的 `sample_events`、`sample_sender_scores`、`sample_receiver_scores`、`sample_validation` 四个 CSV 仍存在。已复现旧 `sample_events.csv` 中残留 8 行。

**空结果结构。** pooled 模式仅在事件非空时添加 `inference_mode`；有效但为空的结果缺此列，置换提前返回分支也没有统一补齐运行统计 attrs。按相同 schema 读取非空/空结果的程序会遇到 KeyError。

**参数 JSON。** `json.dumps()` 默认允许非有限数值。审查时 A05 中的非有限随机种子使导出的 parameters 文件包含字面量 `NaN`，严格 JSON 解析器会拒绝该文件。A05 修订后主入口已拒绝该种子，但导出器本身仍缺少严格 JSON 预检，对被调用者修改为非有限数值的参数仍不能保证输出符合 JSON 标准。

**方案。** 一次导出明确管理自己的结果文件集合：写出本次清单，在校验通过后只处理该前缀下由本导出器定义、但本次已不适用的可选文件。统一各模式的固定输出字段和运行统计，空结果仍保留表头。格式预检继续覆盖所有表和参数；参数序列化显式禁止非有限 JSON 数值，同时保留合法 NumPy 标量支持。结果表中的结构性 NA 继续按既定 CSV 规则保存。

**验收。** pooled↔sample-aware、非空↔空、相同前缀重导出均验证；写入前预检失败不得破坏上次结果；参数文件通过严格 JSON 解析；名称/ID 仅输出一次、零与 NA 的 CSV 往返保持正确。
