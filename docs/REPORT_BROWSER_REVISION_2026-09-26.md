# 大量事件报告浏览修订（2026-09-26）

> 本文保留该阶段的设计与验证记录。当前通用/所选报告已分离，解释索引已整合进列表；最新行为以 [交付说明](POSITIVE_DELIVERY_0.8.md) 为准。

本地版本 0.7.1。实现已确认的报告展示方案；评分、置换、FDR、selection
条件及交付文件范围保持原行为。报告仍是一个可离线打开的 HTML。

## 修订内容

| 部分 | 之前 | 现在 |
| --- | --- | --- |
| 事件列表 | 固定前 100 行预览 | 内嵌全部报告范围内事件，默认每页 50 行，支持 25/100 行和跳页 |
| 搜索 | 无 | 按发送细胞、接收细胞、HMDB、代谢物名称、受体搜索；可指定单字段，跨全部页面匹配 |
| 排序 | 固定报告原排序 | 点击列名切换升降序；数值列按数值比较，NA 始终末尾；可恢复原排序 |
| 展示范围 | 原始/入选/解释数量 | 保留全局计数，另显示当前表格搜索命中数、页码和已生成解释 X/N |
| 解释定位 | 从上至下阅读 | 解释目录、表格中的解释链接、返回目录/列表；链接会展开对应章节 |
| 未解释事件 | 没有统一标记 | 明确显示“未生成详细解释”，提示进一步筛选并生成报告 |
| 解释展开 | 所有事件图直接展开 | 首个解释展开，其余折叠；深层明细继续折叠 |
| 禁用脚本 | 静态报告 | 前 50 行明确标为静态预览，解释仍可手动展开；完整数据可导出 CSV |

搜索采用不区分大小写的子串匹配，去除查询首尾空白。代谢物名称只用于展示和搜索；
事件与解释链接仍由 sender + receiver + HMDB + sensor 确定。报告序号保持生成时
的顺序，翻页和排序不会把解释错误地关联到另一个事件。

## 保持的行为与边界

- `detail_n=10` 仍为 selection 报告默认；0 不生成解释，None 解释全部。
- 事件列表中的搜索、排序和翻页只改变显示，不改变 selection、概览、CSV、原始值，
  也不重新选择“前 10 个解释事件”。排序靠前的事件不一定代表全部通讯模式。
- `events=[...]` 手工请求仍全部解释；保留样本限定、重复指定及未评分候选事件。
  目录标注样本范围，未出现在事件表中的候选事件也能通过目录查看。
- 未传 selection/events 的报告仍展示全量事件，不自动生成逐事件解释。
- `save(report=True)` 仍交付完整 H5、全量 CSV 和 HTML；筛选 CSV 仍由
  `focus.to_csv(path)` 显式导出。不额外自动生成 JavaScript、JSON、PNG 或 PDF 文件。
- 事件列表只渲染当前页 DOM，但全部行的数据嵌入 HTML；文件大小和浏览器数据内存
  随事件数增长。折叠不会减少已生成图表，限制解释规模仍靠 detail_n。
- 浏览器中点击未解释事件不会启动 Python 或后台计算。需要进一步筛选后生成另一份报告。
- 其他明细表仍最多预览 100 行，每组解释图仍最多展示 10 个样本单元。

focus = res.select_events(sender_labels=["A"])
